# MeetFlow 架构与数据设计

知华科技（上海如静知华信息科技有限公司） · https://www.zhuatech.cn/ · 微信 zhuatech / zhuatech2

## 组件

Vue3 → 同源Nginx → Spring Boot4 API → MySQL8.4。默认只有前端回环8102端口；后端8080和数据库3306仅在Compose网络可用。Flyway启动执行V1/V2，JPA ddl-auto=validate。北京时间只用于规则和展示，数据库与服务计算使用UTC。

| 表／实体 | 含义与关键约束 |
| --- | --- |
| account / access_role / role_permission | 账号、角色、权限关系；账号密码BCrypt；角色范围有限枚举 |
| department / permission / nav_menu | 部门、权限代码、菜单权限外键 |
| dictionary_entry / system_setting / audit_event | 类型字典、固定代码参数、受范围限制审计 |
| meeting_resource | 代码唯一、部门及负责人外键、版本、容量和开放规则 |
| meeting_booking | 资源、申请人、部门、审批人外键，版本和状态，计划时间、实际时间、占用及提交规则快照 |
| resource_block | 资源外键、维护区间、创建人、ACTIVE/CANCELLED、版本 |
| booking_event | 每次状态变化、操作人、原因及单据JSON快照，不可通过API改写 |
| booking_command | 操作人＋请求键唯一，单据及载荷摘要，控制相同请求重试 |

结构和索引以 `backend/src/main/resources/db/migration/` 为准，不手工写初始化DDL。

## 同一资源上的并发

写事务使用READ_COMMITTED。先锁资源行，再读取当前单据，清理本资源的到时预约，校验版本、权限、规则和区间，最后写单据／命令／事件／审计。同一资源上的提交、审批、签到、提前结束、维护和规则变更使用相同锁顺序。不同资源可并行操作。

草稿不持有时段。占用查询包含PENDING/CONFIRMED/IN_USE/COMPLETED，条件为实际占用起点 `<` 新结束及占用终点 `>` 新开始。已完成预约只在剩余缓冲段影响新预约。实际提前签到起点也进入占用计算。快照缓冲不会被日后资源规则修改重写。

版本防止旧页面写入。幂等键只在同一操作人下有效，摘要绑定动作及载荷；同键不同载荷拒绝。同内容成功重试返回当前记录，授权仍重新验证，不跳过权限。新动作或改变内容应使用新键。历史命令与事件随预约保留；仅未提交草稿可删除相关记录。

## 数据权限与隐私

业务接口各自验证权限和数据范围。资源私有性控制目录可见；预约详情控制申请人／指定审批／部门或全范围。共享资源的其他无权预约在日历中没有单据ID、标题、申请人或状态。系统管理员可阅读所有授权记录，但审批仍要求指定独立审批人。

目录最多10000条，预约列表数据库分页，统计超过10000条明确拒绝。当前设计适用于单业务库、单后端实例。没有跨库、多租户或高可用调度承诺。自动清理按资源独立事务执行；异常日志不写密码或预约载荷。
